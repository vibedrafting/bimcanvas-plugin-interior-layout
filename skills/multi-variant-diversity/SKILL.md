# 多方案差异化方法（Step3）

执行本方法：**收割并组织** Step2 的**分区思维**（已产出方式A/B 等 ≥1 种切分）与**顺序思维**两份草稿——它们各自已收敛出布局思路，**是变体的首要来源**。把这些已探明的思路**去重、并列成 N 个方向层变体**（每个给一句设计方向 + 唯一硬锚点 `anchorSeed`），**而非另起炉灶按"选最长墙"重排**。

> WHY：双思维是本步空间推理的来源；绕过它自行按"选最长墙"重排，等于丢掉上游已完成的推理、把被淘汰的"唯长墙"偏见请回来——正解会被一个从零重排的方案挤掉（本户型"北墙连续衣柜"正解被丢、衣柜钉到床对面西墙的真因）。

## 纪律

- **【必须】**默认中文。先读后写；**【禁止】**给文本/JSON 传 `pages`。不修改 `baseline/`。
- F3 排除式（见下）在自主模式下自动排除 + 上报，不替用户终选。

## 入场读取

调用方给出 `designZoneId` 与用户诉求。**已附上游材料（空间骨架 + 双思维草稿）时直接使用，免读父 DESIGN.md**；未附时读父 `DESIGN.md`「用户诉求 + 项目基础信息」「设计区空间骨架」「方案草稿」。通过 `Skill` 加载 `load-design-knowledge`（`stage: 多方案`，`roomType`）——**从房间策略取本房型的主家具清单与各家具墙面判据**（卧室：床/衣柜；卫生间：台盆/淋浴/马桶；客厅：沙发/电视柜；按实际 roomType 取）。每变体 `narrative` **≤8 行**（narrative 是方向 WHY，不是方案书）。

## 设计哲学：差异化在【方向层】，不在配置层

用户期待的"多方案"是**几种思考方式的差异**（睡眠优先 vs 换衣动线优先 vs 空间策略优先），不是"同一思考方式下家具排列组合的结果"。每个变体只锁定 **1 个核心决策点**（`anchorSeed`），其余决策（主家具选墙、是否 L 形、可选家具位置、阵列方式）**全部交给落地分身全局重判**——其双候选评估、L 形门槛、阵列前置扣减、闭合预检规则会在锚点约束下自然激活，产出"该方向下最好的方案"。

> WHY：把具体家具配置写死在变体里，落地分身就只能"兑现已经决定的画面"、失去全局重判机会——这是 multi-plan 质量崩溃的根因。锚点锁方向、知识管落地，才能既多样又不失质量。

## 【必须】差异化只在合格设计之间——不靠欠设计凑多样

每个变体**首先必须是一个合格设计**，差异化只在合格集合内取。**禁止**用"欠设计"制造差异：把最适收纳长墙留空、把应放且放得下的可选家具（如梳妆台）省略、把单面最长实墙整面空置——这些不是"开放/留白/步入式"，是降级。一个变体若达不到 `design_evaluation` 的「家具最优布局 / 储物充分」底线，**不得**作为变体报出，哪怕它"看起来和别的不同"。

> WHY：用户买的是"几个都好、但各有取向"，不是"一个好 + 两个凑数"。差异化是在合格设计的解空间里选不同的点，不是降低质量下限来拉开距离——概念词（开放式衣帽间 / 留白美学）不构成欠设计的合理化理由。宁可 `proposedN` 少而精（N 自适应本就允许只报实有合格数），也不靠降级凑数。
> ❌ 实测反例（Test #3）：`dressing-corner` 把黄金收纳墙（北墙东段）留空、衣柜挤进小角致储物严重不足，以"步入式"包装；`east-bed` 把最长西墙 4850mm 整面空置且省略本可放的梳妆台，以"留白增加空间感"包装——两者都是欠设计冒充差异化。
> ✅ 正确：三个变体应各自先过储物充分/家具最优底线，再在"床头墙取向、收纳组织方式"等**合格轴**上拉开差异。

## 每变体产出：四字段契约（+ 查重键）

| 字段 | 性质 | 内容要求 |
|------|------|---------|
| `direction` | 一句话 | 本变体的**设计方向**核心句。**禁止写具体家具配置**（"北墙满墙衣柜"是配置不是方向；"以收纳功能为视觉锚点"是方向）。 |
| `narrative` | 一段话 | 本方向**为什么值得探索** + 设计哲学差异。给落地做决策的"WHY 输入"，**不是约束**。可选家具建议可带在此（供落地参考，不参与去重）。 |
| `anchorSeed` | **最多 1 条硬锚点** | 本变体的核心识别约束，落地必须兑现。三种类型见下表。 |
| `avoidance` | 一句话（可选） | 本方向应避免的反模式——用于区分兄弟变体的设计哲学。**禁止列具体家具禁止清单**。 |
| `expectedWalls` | **查重键（仅此用途）** | 该方向**预期的主家具墙面归属**，严格 `家具:墙名\|家具:墙名` 格式——**禁尺寸 / 段位修饰（"南段""全段"）/ 括号注释 / 附属家具（窗帘、床头柜不进）**。它不会传给落地、不构成锁定（落地在锚点下仍全局重判），只用于比对"两个方向是否会落到同一布局"。**本步只到墙名层——禁算精确坐标 / 禁做重叠检测（坐标与碰撞是 placement 的职责，这里算了 placement 也会全局重判、纯浪费 + 抽象泄漏）。** |

**anchorSeed 三种类型**（数量恒为 1 条，类型任选其一）：

| 类型 | 锚定什么 | 填法模板 |
|------|---------|---------|
| **单家具锚点** | 一个主家具固定到某墙面/位置 | `<家具名>=<墙面/位置语义>` |
| **家具组合关系** | 两件家具的相对组合形态 | `<家具A>+<家具B>=<组合形态(L形/对位/并排)+位置>` |
| **空间策略** | 跨家具的整体空间组织逻辑 | `<策略名>=<空间区域语义>`（如"主收纳锚点=入口侧连续段（允许跨区）"） |

> WHY：三种类型对应三种思考路径——从哪件主家具开始锚 / 让哪两件家具形成什么组合 / 用什么空间组织逻辑。若所有变体都是单家具锚点（"床/衣柜分别放哪"），差异化退化为一维排列组合，必然漏掉组合/策略层面的方案。**变体应尽量跨锚点类型分布。**

❌ 反例（锚点类型狭化）：direction 说"收纳整合至延伸区、释放主体区"（空间策略），anchorSeed 却写 `主衣柜=延伸区`（单家具锚点）——落地被锁死在延伸区短墙内，不会把柜列延伸到与之连续的主体区墙段。✅ 应写 `主收纳锚点=入口侧连续段（允许跨主体区+延伸区）`，保持与 direction 同层级。

## 【必须】相异性护栏：expectedWalls（预期落点）两两不同

相异性判据是**预期主家具墙面归属两两不同**——不是锚点不同、不是叙事不同、**也不是"分区与否"不同**（分区是组织手段，家具落点相同就是同一方案）。双思维种子里**预期落点相同的合并成一个**；双思维两条路径收敛到同一布局时，那就是 `proposedN=1`——这正是"收割组织"的本意，不丢人、不强凑。**产出 variants[] 前自查：各变体 expectedWalls 归一化（剥括号修饰/空白）后两两不同；有雷同者合并、减少变体数。**

> ❌ 实测反例：报了两个变体——"床=西墙"（单家具锚点）与"北区收纳带+南区睡眠带"（空间策略锚点），锚点类型确实不同，但本户型里两个方向**必然收敛**到"床西墙+北墙L柜+梳妆台东墙₁"同一布局，落地后用户看到两个一模一样的方案。锚点是思考路径，**用户买的是看得见不同的布局**——查重必须在预期落点层做。

落地后编排层还会对各方案实际 modules 做事实查重，实质雷同会在对比表被公开标注，所以不要侥幸。

## 【禁止】以假想用户偏好为差异化依据

差异化依据必须是**空间事实或思考路径差异**，禁止发明用户从未表达的偏好来给变体造叙事。

> ❌ 反例（实测事故）：为差异化写"西墙整段释放为纯粹留白——适合对西墙有特殊使用意图的用户"。用户从未表达该意图，这句虚构叙事却被下游当成设计约束，压死了梳妆台的唯一可行位。✅ 变体的价值由空间组织逻辑自身说明，不需要假想一个喜欢它的用户。

## N 自适应：收割双思维的思路，去重后有几个报几个

`proposedN` = **双思维收敛思路去重后、实质不同的可行方向数**（1~4，软上限 4，默认上限取 `args.n` 否则 3）。
- **首要来源 = 双思维种子**：分区思维的各切分（方式A/B…）+ 顺序思维各自收敛的布局思路，逐个提炼成 `direction + anchorSeed`、去重并列。
- **不足不强凑、不重复**：种子去重后只有 2 个就报 2 个；只剩 1 个 → `proposedN=1`（后续跳过选拔与裁决、直接落地）。
- **补充须有依据**：仅当①种子去重后明显偏少、或②确有种子未覆盖且**明显更优**的方向时，才补一个新变体，并在 `narrative` 写明补充依据；**不补"换面长墙重排"这类绕过双思维的方案**。

> ⚠ 反模式：丢开双思维、自行按"选最长墙 / 不同优先级"穷举墙归属组合；或为凑数把同一锚点换叙事报两个。✅ 正确：以双思维收敛的思路为种子去重并列，不够就报实有数，要补充先给理由。

## slug 命名规则

- 字符集 `[a-z0-9-]`、长度 ≤30、语义清晰可读（如 `north-storage` 而非 `alt-1`）、同批次内不重复。
- **不加 `alt-` 前缀**（那是 relocation 的命名约定）。

## F3 排除式（自动化）

如出现"显然不合理"的候选（如"床面对镜子""开门即对衣柜门"），**自动排除该候选并上报排除理由**。只做**排除**，**不替用户做终选**（终选交 Web 端视觉决策）。

## 产出（结构化 variants[]，交调用方）

产出结构化结果，至少含：

- `proposedN`：按预期落点去重后实质不同的可行布局数（1~4，最终落地数 = `min(proposedN, args.n||3, 4)`）。
- `variants[]`：每项 `slug` / `direction` / `narrative` / `anchorSeed` / `avoidance`（可选）/ `expectedWalls`（仅查重）；**各变体 expectedWalls 两两不同**。
- `excluded[]`：被自动排除的候选及理由（如有）。

调用方据此：①写父 `DESIGN.md`「## 多方案战略层概述」节（每变体列 slug/方向/锚点/预期布局/避免/叙事 + 自动排除条目）；②把 `variants[]` 连同上游材料（空间骨架/双思维草稿）作为 args 传给扇出 workflow 落地。**本方法不写盘、不派发子任务。**
