# 顺序思维方法（Step2）

执行本方法，提供与分区思维并行的**第二条多样性轴**。产物为「家具 → 墙面归属 + 相邻关系」子段，交调用方写入父 `DESIGN.md`「方案草稿」节。

## 线性思维框架声明

思维框架是**线性优先级驱动**：不先做空间分区，而是从最主要的家具开始，**按重要度依次锁定墙面**（如卧室：床 → 衣柜 → 梳妆台 → 可选家具）；每锁定一件，再在其约束下决定下一件，逐件推进直到家具配置成型。

- **不另造一套设计知识**。优先级链与房间策略**全部来自 references**：跨房间优先级 `design_principles.md` 第三节（锚点 → 主要 → 可选）+ 对应房间策略文件的家具优先级清单。只是用"逐件锁墙"的顺序去消费这套既有知识。
- 与分区思维的差异**只在"先分区还是先排序"的框架**，底层知识共享同一套 references。
- 产物是**"家具 → 墙面归属 + 相邻关系"**，**不写精准坐标**（坐标是落地的事）。

## 纪律

- **【必须】**默认中文。先读后写；**【禁止】**给文本/JSON 传 `pages`。不修改 `baseline/`。
- 取舍点：可交互主控可按需 `AskUserQuestion`（SEAM）；默认按推荐继续并标 `[自动代决]`。

## 入场读取

调用方给出 `designZoneId`。**已附上游材料（空间骨架）时直接使用，免读父 DESIGN.md**；未附时读父 `DESIGN.md`「设计区空间骨架」节。通过 `Skill` 加载 `load-design-knowledge`（`level: L2`，`roomType`）取优先级链与房间策略；必要时调 `get_zone_boundaries`。草稿子段 **≤30 行**（中间产物双倍收费）。

## 关键触发器

- 依 `design_principles.md` 第三节优先级（锚点 → 主要 → 可选）+ 房间策略清单，**从最重要家具起逐件定墙**：先锚点家具（功能核心，由空间决定、几乎无选择），再主要家具（由锚点 + 空间共同决定），最后可选家具（功能补充）。
- **别落下可选家具**：主家具锁定后，顺手给梳妆台等可选件想个不碍事的去处、为主家具让路；没合适位就略过。
- 每件家具记录**墙面归属 + 与已锁家具的相邻关系**，不下沉到坐标。
- 锁墙过程中若遇重要度相近的两件家具争夺同一墙面等取舍点，按推荐顺序继续并标 `[自动代决] <取舍 + 理由>`。

## 产出（交调用方写父 DESIGN.md）

**【必须】第一行必须是 markdown 标题 `### 方案草稿 · 顺序思维`**（首字符即 `#`）；**禁前缀任何散文 / 英文推理段 / 代码围栏**——内容被写入父 DESIGN.md，首行非标题会导致 anchor 落空、内容堆到文件末尾污染父文件。结构示意（照此组织，不要当代码块包裹）：

### 方案草稿 · 顺序思维

- 锁墙顺序（按重要度）：1. [锚点家具]→墙面 / 2. [主要家具]→墙面 / 3. ...
- 相邻关系：...
- `[自动代决] ...`（如有；无则写"无"）

只产出上述子段内容本身，不写精准坐标、不描述编排时序。
