# 父文档落盘纪律（design-doc-upsert）

主控在场景①里是父 `DESIGN.md` 的**单写者**（Step1-3 各节 + 方案对比节都由主控产出并写入，落地分身只写各自 `{slug}/` 级文件、不碰父）。单写者顺序写 = 同一文件永不并发 = 无 last-writer-wins 覆盖。本纪律保证写入**机械、确定、幂等**。

IMPORTANT: 写入是**机械 upsert**，不是创作。把产出的节文本原样写入，**不在写入环节改写内容、增删字句、补充评语**。设计判断在感知/规划/多方案各方法里已做完，这里只负责"把成品节块幂等放进文件"。

## 适用时机

主控每完成一个产出节就调用本纪律写父一次（也可多节一次写入）：
- 感知后：`## 用户诉求 + 项目基础信息`、`## 设计区空间骨架`
- 规划后：`## 方案草稿`（含 `### 方案草稿 · 分区思维` / `### 方案草稿 · 顺序思维` 子节）
- 多方案后：`## 多方案战略层概述`
- 扇出 workflow 返回后：`## 方案对比`（用 return 的 `comparisonTableMd`）

## 净化纪律（写入前，防脏标题事故）

对每个待写 section 文本，写入前先净化：

1. **剥整体代码围栏**：若整段被 ` ```lang … ``` ` 包裹，去掉围栏，取内部内容。
2. **剥首标题前的散文/英文前言**：定位首个 markdown 标题行（`^#{1,6}\s`），把它之前的散文/英文推理段剥掉，从该标题行起取。
3. **期望锚优先**（已知本节标题关键词时）：定位首个**包含该关键词的标题行**，从该行起取——跳过中途夹带的带标题草稿（如 `### Analysis Summary` 中间稿，实测曾泄漏进父 DESIGN.md）；无匹配则回退到第 2 步的首标题行为。

> WHY：产出方偶尔会在正文前夹带散文或带标题的中间稿；不净化直接写会让 anchor 落空、内容堆到文件末尾、脏标题（`dc41170` 事故）泄漏进父合同。净化只做"剥到正确标题"，**不改节内文字**。

## 幂等 upsert 算法（机械执行，不偏离）

1. `Read` 父 `DESIGN.md`（不存在则视为新建）。
2. **文件不存在**：新建，依次写入各净化后的 section 块（块间空一行）；不写 frontmatter（指针由 MCP 工具写）。
3. **文件已存在**：对每个 section 块，取其**首行标题**（含 `#` 级别）作为 anchor：
   - **anchor 已存在**：用本块**整体替换**"从该标题行起、到下一个**同级或更高级**标题行之前（或文件末尾）"的全部内容。仅替换该节，**不动其它节**。
   - **anchor 不存在**：把本块**追加**到文件末尾（前面空一行）。
4. 多块按顺序逐个处理；处理完一个再处理下一个。
5. `Write`/`Edit` 回写，保持其它已有内容（含 frontmatter、其它节）原样不动。

> **【Edit 唯一定位】**用 `Edit` 替换某节时，`old_string` 须含**足够上下文唯一定位**该标题——父 DESIGN.md 常有相似标题（如 `## 方案草稿` 与其下的 `### 方案草稿 · 分区思维`/`· 顺序思维`），只写 `## 方案草稿` 会撞多匹配报错（实测）。先 `Grep` 确认锚点唯一，或带上节内首行内容一起定位。

> 标题级别判定：`## X` 是 2 级，`### X` 是 3 级。替换 3 级节时边界是"下一个 `###`/`##`/`#`"；替换 2 级节时边界是"下一个 `##`/`#`"。

## 禁止事项

- **【禁止】**改写、润色、概括、扩写交来的节文本——逐字写入。
- **【禁止】**自行新增标题、调整节顺序、删除未被本次覆盖的既有节。
- **【禁止】**写入或改动 frontmatter（`adopted` 等指针由 `adopt_variant` MCP 工具写）。**仅当需要编辑既有 frontmatter 时用 `Edit`，禁用 `Write` 全量重建（会丢正文）。**
- **【禁止】**Read 父文件时传 `limit`（截断读会丢内容，导致回写覆盖）。
