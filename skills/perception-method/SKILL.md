# 感知方法（Step1：定调 + 空间骨架）

执行本方法，一次完成两件事：**§1 战略定调** + **§2 空间骨架**，产出两节文本交调用方写入父 `DESIGN.md`。

IMPORTANT: 必须使用工具调用 API（function calling）调用 MCP 工具，禁止输出 `<mcp__xxx>...</mcp__xxx>` 文本。

## 纪律

- **【必须】**默认中文思考与产出。
- **【必须】**先读后写：Read 默认 `{"file_path":"绝对路径"}`，仅分段读长文本时加 `offset`/`limit`。**【禁止】**给文本/JSON/图片传 `pages`；遇 `Invalid pages parameter` 下一次必须删 `pages`，不得原样重试。
- **【必须】**不修改 `baseline/`，不修改任何①层冻结配置。
- **战略选择点处置**：若调用方为可交互主控，关键战略选择点（路径取舍 / 锚点歧义 / 诉求与户型矛盾）可按需 `AskUserQuestion` 征询用户（SEAM）；默认不暂停，按推荐方向继续并以 `[自动代决] <决策 + 理由>` 显式标注，不静默吞掉。
- **本方法不另造设计知识**：空间阅读三要素、安静度判据等本体由 load-design-knowledge 按阶段注入（不在本 skill），本 skill 只装感知执行动作与护栏。

## 入场动作

调用方给出 `designZoneId`（设计区节点 path）与 `originalUserRequest`（用户原始诉求）。依次：

1. Read 当前项目 `README.md`（意图理解与材料定位）；若设计区父 `schemes/{designZoneId}/DESIGN.md` 已存在，读取已有上下文（不覆盖）；必要时 `Glob` 定位项目级冻结配置（只读）。
2. `mcp__interior-layout__get_zone_boundaries({ zoneIds: [designZoneId] })` —— 取设计区边界 / passage 几何。
3. `mcp__canvas__canvas_vision`（**识图模式·传 prompt**）—— 取当前户型的**文字视觉证据**（deepseek 无 vision，必须传 `prompt` 让识图服务返回 `resultText`）。**【截图范围·禁 room 模式】**`designZoneId`（`rz_*`/`dz_*`）是 zone id 非物理房间 id——传 `projectPath` + `prompt` + `viewport:{mode:"zone", zoneId:"<designZoneId>"}`；**禁** `viewport.mode=room`/`roomId`（必报 `Room not found`）；图源与截图范围二选一。
4. 通过 `Skill` 加载 `load-design-knowledge`（按【感知】阶段取对应 references）——取品质维度（load-design-knowledge 注入）作为空间阅读判据。

## §1 战略定调（产出 strategySec）

- **用户代言**：把用户诉求翻译成本轮设计的目标与偏好——用户偏好是后续用户终选与方案对比的输入，务必明确记录。
- **战略取舍点显式化**：主动设计路径中的战略选择、关键锚点歧义、用户诉求与户型明显矛盾、硬约束与户型条件冲突——按推荐方向继续并标 `[自动代决] <决策 + 理由>`，交后续环节与用户复核。**但不在此锁定洁具放哪面墙 / 沿哪面排**——选墙是 Step2 规划的布局决策（见 §2 护栏），感知不抢做。
- **输入与户型矛盾存疑**：用户诉求中当前户型明显无法兑现的要求，标 `[自动代决]` 记录存疑，不静默吞掉。
- **功能完整性意识**：留意诉求隐含的功能清单（每类功能后续都应有对应家具），为方案对比的功能完整性埋判据。
- **邻接噪音战略留痕**：当用户诉求含睡眠/安静偏好、且空间阅读（§2）发现候选主墙背靠 LivingRoom / 公共空间 / 卫浴排水等噪音源时，**不得静默把噪音墙当优选依据**——标 `[自动代决] <安静度 vs 候选墙权衡>` 留痕（安静度是排序偏好、非淘汰依据）。

## §2 空间骨架（产出 spaceSec）

**独立理解当前户型**——**永不读取参考图、参考分析或他人设计意图**（骨架被参考幻觉污染，整条设计链地基就坏了）。**执行动作**：从品质维度（load-design-knowledge 注入）逐项核查当前户型，产出动线 / 纵深 / 采光 / 安静度 / 潜力风险结论。三要素的**定义**见 load-design-knowledge 注入的空间认知知识，本节只执行核查、不重述定义。

### 【必须】房型保真护栏（防地基污染）

- **只描述客观空间属性**：动线 / 纵深 / 采光 / 安静度 / 墙面长短与完整性（有无窗、有无门段）。**禁写房型专属功能命名**——电视墙、床头墙、沙发区等是 Step2 双思维依房间策略才能下的功能定性，骨架阶段一律不写。
- **墙面中性化**："最长完整实墙"只陈述为**墙面资源**（长度 / 完整性 / 无窗无门），不预判功能。
- **不决定洁具承载墙 / 不预设排布墙**："哪面墙放洁具、洁具沿哪面排"是 Step2 规划依房间策略（开阔侧 / 台盆墙长优先等）才能定的**布局决策**——感知阶段（尚无房型策略在手）**一律不做**，只客观列墙面资源。**禁**写"某墙最优质 / 最长 → 选它承载洁具"这类预判（实测教训：感知抢先锁"西墙=唯一承载墙"，后续规划只确认不复审，开阔侧规则翻不动已锁的墙）。
- **禁引用未加载的设计知识**：只引用本次已加载的房间策略与品质维度（load-design-knowledge 注入）；禁凭训练先验编造"根据某房型策略……"的幻觉引用。

### 【必须】邻接噪音核查（标"安静"前置·执行动作）

**执行动作**：给任一墙面下"安静"结论**之前**，先核查其背靠的相邻 zone / 房间类型——**【必须】Read `baseline/rooms.json`，对设计区每面候选墙坐标匹配背靠的 room**（找与该墙平行、在墙厚 ~200mm 内的相邻 room 边），把"背靠 {room.name}（type）"作为几何事实记入骨架。`get_zone_boundaries` 只返回同区子分区的 passage 邻接、**不含跨 room 邻接，故跨 room 必走 `rooms.json`**；**禁以"无门无窗"推定外立面 / 室外**。**判定映射（背靠什么 = 噪音源、如何降级）见 load-design-knowledge 注入的空间认知知识·安静度判据**——本节只强制"标安静前必先核查邻接"这一动作，不重述判定全文。陈述邻接房型不违反房型保真护栏（护栏禁的是给本 zone 墙面贴功能命名）。

**【必须】**空间骨架只写空间骨架，**不写具体家具坐标**。

## 产出（两节文本，交调用方写父 DESIGN.md）

产出两段文本，**每段首字符必须是 markdown 标题**（禁前缀散文 / 英文推理 / 代码围栏——内容将被写入父 DESIGN.md，首行非标题会让 anchor 落空污染文件）。交调用方按 `design-doc-upsert` 纪律写入父 `schemes/{designZoneId}/DESIGN.md`：

- `strategySec`：以 `## 用户诉求 + 项目基础信息` 开头，含子节：`### 用户诉求`（核心目标 / 偏好 / 明确约束）、`### 项目基础信息`（设计区身份 / tags / 边界条件）、`### 战略取舍与存疑`（`[自动代决]` 条目，无则写"无"）。**≤25 行。**
- `spaceSec`：以 `## 设计区空间骨架` 开头，含子节：`### 当前户型空间阅读`、`### 动线与纵深`、`### 采光与安静区判断`、`### 初步设计抓手 / 潜力与风险`。**≤40 行。**

> WHY 产出预算：两节是下游规划/落地的输入，不是给人看的文档——多写的每个字都在双倍收费（你生成一次、下游各读一次）。写结论与判据，不写过程散文。
